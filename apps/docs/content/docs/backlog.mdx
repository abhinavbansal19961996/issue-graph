## Reconcile an open backlog

Reconcile discovers open issues and PRs without requiring labels, crawls their reference neighborhoods, and assigns evidence-backed actions:

```bash
issue-graph reconcile --repo owner/repo --format markdown
issue-graph reconcile --repo owner/repo --format json --no-snapshot
```

Replace `owner/repo` with a repository you can read. Default `--format auto` chooses Markdown for a terminal and JSON for a pipe. Use an explicit format in integrations.

The versioned report includes counts, ordered items, structured evidence, crawl limits, repository-level history when available, and contextual next steps. Evidence entries contain `code`, `summary`, and `related` node keys, so an agent can branch on stable reasons instead of parsing prose.

## Treat actions as a verification queue

| Action | What to inspect before acting |
| --- | --- |
| `verify-completed` | Current code, acceptance criteria, and live behavior for an issue linked to merged work |
| `close-superseded` | Scope parity with merged work and contributor credit |
| `verify-superseded` | Both implementations and whether the newer merged work covers the older PR |
| `resolve-competing` | Competing PRs, their differences, and the contributors involved |
| `repair-closing-link` | A closing claim without the expected GitHub relationship |
| `review-open-pr` | The exact PR head through the repository's review gate |
| `keep-linked` | Related work still active |
| `keep-untracked` | Reproduction and investigation before prioritizing implementation |

These are recommendations, not GitHub mutations. No issue is closed, PR merged, or comment posted by reconcile. A merged relationship is not proof of working behavior.

## Check inventory coverage

Seed discovery paginates GitHub search, bounded by `--max-nodes` and the 1000-result search ceiling. The default node cap is 80; `--max-nodes` accepts 1 to 1000. Depth, hub, concurrency, and per-node limits still apply to the resulting graph.

Inspect `limits.seedLimitReached`, `limits.cappedOut`, and `limits.fetchFailures`. A report with these limits is not proof of a fully reconciled backlog. Increase the budget, re-seed an omitted neighborhood, or retry access failures as appropriate. A successful process exit does not certify full reconciliation coverage.

See [Graph](/docs/graph) for limits that cannot be removed simply by increasing the node cap.

## Compare repository history

Reconcile normally saves under `~/.issue-graph/reconcile-owner-repo/`. Unlike graph history, the comparison is keyed by repository rather than the current open seed list, so it can track action changes even when the backlog changes or becomes empty.

History reports added, changed, and resolved actions plus coverage regressions and recoveries. Incomplete coverage suppresses unsafe new/resolved claims. `--no-snapshot` prevents saving a new report but does not prevent reading an existing baseline.

## Plan the next action

```bash
issue-graph plan --repo owner/repo --format markdown
issue-graph plan --repo owner/repo --format json
```

Plan reuses live reconciliation and discussion signals to produce:

- A ready execution queue.
- An investigation queue for items needing evidence.
- Blocked work, such as draft or conflicting PRs and issues with active related work.
- A single `next` recommendation when coverage permits.
- A structured `decision` for the observed next-action neighborhood.

Cleanup and verification precede implementation review. Within lanes, ordering uses readiness, discussion heat, and visible inbound references. The rules are deterministic for the same captured evidence and evaluation time; changing live data can change the queue.

Missing open seeds or capped neighborhoods make the queue provisional and suppress `next`. Failed neighbor references are quarantined to affected items so unrelated work can remain actionable. Do not hide these uncertainties from the consumer.

## Compare competing PRs without selecting a winner

For competing PRs, `decision` labels relationships and compares draft state, review state, mergeability, diff size, file counts, and update times. `reviewFirst` orders inspection only. It does not prove correctness, merge readiness, or which implementation should win.

`blockedBy` comes from visible active GitHub relationships. Plan does not infer product dependencies from issue prose. Re-run after a merge or closure to refresh the queue, and use separate review and authorization before changing GitHub.

Plan writes no snapshots and does not support HTML export. Use `--format json` for its machine report, not graph's `--json PATH`. See [Reference](/docs/reference) for command-specific output contracts.
