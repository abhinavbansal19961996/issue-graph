## Count open PRs without a graph crawl

Use explicit repository and author scope:

```bash
issue-graph status --repo vercel-labs/portless --author ctate,Railly
issue-graph status --repo vercel-labs/agent-browser --repo vercel-labs/portless --author ctate,Railly
issue-graph status --repo vercel-labs/portless --author ctate,Railly --view projects
issue-graph status --repo vercel-labs/portless --author ctate --view prs
issue-graph status --repo vercel-labs/portless --author ctate,Railly --json
```

Both `--repo` and `--author` are required. Repeat `--repo` for multiple repositories; repeat or comma-separate `--author`. Scope matching and deduplication are case-insensitive. Authors are not an inferred organization membership list.

The default `authors` view includes repository/author rows with zero counts when coverage supports zero. `projects` shows project totals and per-author counts. `prs` shows underlying PRs, titles, URLs, head evidence, assignees, requested reviewers, and follow-up graph commands.

## Choose an output format

TTY output defaults to an aligned table with narrow-terminal fallback. Pipes default to versioned JSON. Use `--format auto|table|markdown|json` to choose explicitly. `NO_COLOR` disables styling; progress and headings use stderr.

```bash
issue-graph status --repo vercel-labs/portless --author ctate,Railly --format markdown
```

In status only, `--json` means JSON on stdout and takes no filename. Graph's `--json PATH` has a different contract. Status JSON schema version 1 includes scope, query timestamps, per-repository coverage, PR evidence, author and project rows, totals, and next steps.

## Read counts without losing uncertainty

Each metric contains `count`, `prIds`, and `unknownIds`. A `null` count means unknown, not zero. Known matching IDs remain useful as a lower bound. Human views display `?` for unknown counts.

Check `coverageComplete` and each repository's `coverage` before citing totals. A failed repository invalidates its own aggregate counts and portfolio totals, not complete sibling repositories. Query timestamps describe a collection window, not an atomic GitHub snapshot.

Review-required, changes-requested, approved, no-review-required, and unknown states partition open PRs. Draft, conflict, and unassigned indicators are independent and may overlap those states. Unknown mergeability is not evidence of being conflict-free.

Ready-for-review means non-draft, not approved or merge-ready. For a non-draft/unassigned intersection, filter JSON `pullRequests` by `isDraft === false` and an explicitly empty `assignees` array. Do not subtract independent totals or treat unknown assignees as empty.

Approval is not merge readiness. Status does not inspect CI checks, bot review findings, or coding-review threads, and it does not verify that review comments were addressed. Use separate code and review gates before merging.

## Understand pagination and exit codes

Status paginates repository PR connections rather than relying on GitHub search results. PR pages contain 50 items. Assignee and reviewer-request connections are also paginated.

| Flag | Default | Range |
| --- | --- | --- |
| `--concurrency N` | 4 repositories | 1 to 32 |
| `--max-pages N` | 100 pages per connection | 1 to 1000 |

Caps, access failures, malformed responses, and detectable pagination drift produce incomplete coverage rather than confident totals.

- Exit `0`: complete inventory and, when requested, complete comparison.
- Exit `1`: incomplete evidence or runtime failure. Inspect any partial report; do not treat it as an empty backlog.
- Exit `2`: invalid arguments or incompatible scope/options.

## Save and compare captures

Status writes no snapshot by default. Opt in when you need history:

```bash
issue-graph status --repo vercel-labs/portless --author ctate,Railly --save
issue-graph status --repo vercel-labs/portless --author ctate,Railly --since last --save
issue-graph status --repo vercel-labs/portless --author ctate,Railly --since /path/to/previous.json --json
```

`--save` writes an immutable local JSON capture under `~/.issue-graph/status/<scope-hash>/`. `ISSUE_GRAPH_HOME` changes the status storage root. Captures use restrictive local permissions but are not encrypted or automatically safe to share.

`--since last` loads the latest capture for exactly the same repository/author scope before fetching or saving new evidence. Order and case can differ; the scope itself cannot. `--since PATH` can read a saved snapshot or an older exported status JSON report. Missing, corrupt, future, or mismatched baselines fail explicitly instead of being interpreted as no changes.

`--no-snapshot` forbids status snapshot writes and conflicts with `--save`. It can be used with `--since` to compare without saving the new capture.

## Interpret changes as observations

Human output adds a Changes appendix. JSON adds `history` during comparison and `snapshot` with the saved path when saving. History covers review, draft, conflict, head, assignment, and reviewer-request transitions, plus additions, departures, uncertainty, and count deltas.

PRs missing from the new inventory are queried explicitly to distinguish merged, closed, and unverified departures. Absence alone never means merged. Unknown metadata or incomplete baselines cannot prove an addition or transition. Reconstructed baselines retain their provenance and unknown fields; do not backfill historical facts from today's response.

These are observed state changes, not attribution of who submitted a review or proof of resolved comments. Follow [Graph](/docs/graph) for relationships and [Security](/docs/security) before retaining or sharing captures.
